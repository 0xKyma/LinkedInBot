### World Event Option 1 — interface management / open architecture (MOSA)

An interface specification now carries integration risk that a single prime's programme office used to absorb.

The US Air Force CCA selection split the work in two. General Atomics and Anduril build the airframes. Anduril, Shield AI and Collins compete separately for the autonomy software. A government-owned interface standard holds it together: the Autonomy Government Reference Architecture, which every vendor must meet.

That reads as a clean MOSA move on paper. Decouple the platform from the mission software, update each on its own clock, kill vendor lock.

But interface control documents only work when they are complete and someone enforces them. A-GRA absorbs the integration risk that used to live inside one programme office. Timing, behaviour and failure-mode details get hard when independently competed software meets independently competed hardware in flight test.

A wrong spec means no one owns the integration. So how good does A-GRA actually have to be?

### World Event Option 2 — feedback loops / emergence

Decoupling a system into independent parts changes where the failures show up, not whether they show up.

The Air Force split CCA hardware from autonomy software into two competitions, bound by a government interface standard. The logic holds. Hardware and software move at different speeds, so let them.

The catch is emergence. Integration behaviour does not sit in the airframe or the autonomy stack. It comes out of the interaction. Competing those two layers separately does not remove that behaviour. It pushes the behaviour into the gaps between contracts.

Those gaps run on weak feedback loops. A hardware vendor and a software vendor each optimise their own deliverables, so neither one naturally sees the system-level behaviour that only appears when both run together. Someone has to own that loop deliberately, because no one owns it by default.

The standard is the easy part. Watch who owns the seams.
